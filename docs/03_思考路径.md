# 06 · 思考路径

> **这份不是规则，是"为什么最后长成这样"的记录。**
> 起点、卡点、怎么解的、哪些被否决了 —— 按时间顺序。
>
> 规则本身看 [01_象征物体系.md](01_通用框架/01_象征物体系.md)、[02_塔罗体系.md](02_塔罗分支/02_塔罗体系.md)；
> 实现细节不在此仓库。

---

## 一、起点：一句话

> **把"凭感觉"的解读，拆成可推导、可复现、可检查的规则。**

再往下拆一层，是三个判断：

| 判断 | 为什么 |
|---|---|
| **最小单位是「象征物」，不是「牌」** | 牌是集合，象征物才是原子。用牌当单位，换领域就得重做 |
| **象征物 → 象征物本体，是共识不是规定** | 太阳给所有人光明与温暖，所以"太阳=阳"不是谁拍的 |
| **只谈"结构"，不谈"注定"** | 谈的是当前信息下几种可能，不是预言 |

**所以第一个决定**：这个方法**不认识塔罗**。塔罗只是它的一本字典。

---

## 二、卡点与解法（按发生顺序）

### 卡点 1｜颜色为什么不能和其他象征物一样处理

**卡在哪**：一开始想统一处理，但发现颜色之间本身就有关系 —— 同一个颜色有浓淡，不同颜色之间有对立。

**怎么解的**：给颜色单独加两条规则。

- **深浅**：深 → 进一档，浅 → 退一档，深浅交织 → 不调制
- **对立**：不是任意两个都算，每个领域自己指定；**只有最激烈的那一对会改属性**

**留下的规矩**：顺序是死的 —— 先深浅 → 再对立 → 最后配对判定。颜色以外的象征物**一律不做处理**。

---

### 卡点 2｜属性要不要量化

**卡在哪**：既然有"极阳 / 衰阳"，那强多少、弱多少，是不是该给个数值？

**怎么解的**：**不量化**。属性的变化只为含义服务，不做计量。

- 塔罗这一支：**不输出强度**
- 通用层：可选，用"强对碰 / 弱对碰"这类**档位**表达，不给数字

**为什么**：一旦量化，就会开始比大小，而含义不是可以比大小的东西。

---

### 卡点 3｜两个东西放一起，怎么算

**卡在哪**：阴和阳放一起是"矛盾"，阴和阴是"一致"，那"中和阴"是什么？二值系统（有关系/没关系）表达不了。

**怎么解的**：三态 + 关系位。

| 状态 | 关系位 | 含义 |
|---|---|---|
| 对碰 | 冲突位 | 两边相向，互相顶住 |
| 重叠 | 和谐位 | 两边同向，互相加固 |
| 交汇 | 调和位 | **留白** —— 允许选择的空间 |

**关键点**：**交汇不是"没关系"**，是主动留出来的呼吸空间。这条后来成了整套方法最容易被人记住的地方。

---

### 卡点 4｜正位怎么写才不像词典

**卡在哪**：只写"这张牌代表创造力"就是词典，读者看不出它在**这个位置**上意味着什么。

**怎么解的**：**以圆心为核心，句式「A，即 B」**。

- A：画面里发生了什么
- B：落回那个核心词

**顺带定的**：正位必须写得足够详细 —— 因为逆位要顺着正位每一条往回推。

---

### 卡点 5｜逆位到底怎么推

**卡在哪**：常见做法是"逆位=反义"或"逆位=阻碍"，但那样会把牌读死。

**怎么解的**：**逆位不是反义，是圆心先偏移**。

```
圆心偏移 → 正位含义跟着偏移 → 得到逆位
```

作者原话：**"圆心的设计就是为了逆位而产生的"**。

**四种变化**：
- 方向（完全相反 / 部分相反）
- 显隐（由显到隐；由隐到显极少）
- 时间（只作用于空间层）
- **程度**：不独立，嵌套在上面三种里

**关键决定**：属性不随后天摆设改变 —— 正逆位只改读法，不改零件。

---

### 卡点 6｜牌与牌之间怎么"互动"

**卡在哪**：一张牌有几十个元素，两张牌一配就是几千对，全给出来没法读。

**怎么解的**：四道筛子。

1. **牌内已经用掉的元素不再参与**（剩下的才是可配的）
2. **同景 + 同类目才配**：颜色配颜色、事物配事物；空间层单独一组，方位只配方位
3. **状态用同一张表**：对齐层与类目后，任意一对必有状态
4. **压缩**：同层 + 同类目 + 同状态的对合并成一组

**为什么**：不是"两张牌有关系"，而是"具体的两个元素配上了"。这一步是整套方法从"解释"变成"计算"的地方。

---

### 卡点 7｜三张牌怎么合成一个整体（歧点）

**卡在哪**：多张牌放一起时，如果只两两配对，会得到一堆零散结论，读者看不到"整体在说什么"。

**怎么解的**：**歧点**。

- 三张牌各取一个**同状态**的组合 → 一个因素
- 因素数取三张里**最少**的那一边
- 多个因素合起来 → **整体**
- **整体一旦形成，就不再和谁"对碰"**，只带自己的方向单方面流出

**最难接受的一条**：整体**没有状态**。它不能参与后续配对，只能单向流出去。

---

### 卡点 8｜一张牌怎么拆给别处（瑕点）

**卡在哪**：有些牌的影响是"渗透"的，不是"对上"的。

**怎么解的**：**瑕点**。

- 一张牌拆成按状态划分的碎片
- 碎片各自去找对家的同状态组合
- **用完即弃**：N 片最多配 N 对
- **单向**：碎片流过去就不回来

**关键区别**：**融合 ≠ 叠加**。不是把两句话并排写，而是问"一个落在另一个上，会变成什么"。

---

### 卡点 9｜输出像清单

**卡在哪**：第一版是每张牌一个标题 + 三层硬结构，读完像在念表格。

**怎么解的**（这一轮改了三遍）：

| 版本 | 问题 | 改成 |
|---|---|---|
| V3 初版 | 每张牌一个 `##`，三层结构 | 保持，但补了格式自由 |
| **V2 式分组** | 太像清单 | 按**位置组**分段，段内每张牌一行粗体引出，段末**小结** |
| **三级标题** | 粗体行不好扫读 | `# 报告` → `## 组` → `### 位置名 · 牌名（正逆位）` |
| **互动独立成节** | 互动藏在单牌正文里，看不见 | 段内顺序固定：**单牌 → 互动 → 小结** |

**最后定的骨架**：

```
# {牌阵}解读：{主题}
## 一、{组名}
### {位置名} · {牌名}（正逆位）
### 互动          ← 表格
**小结**：…
## …（每段同构）
## 结构：一条向下的流   ← 只有歧点/瑕点才有
## 总况：{牌名}         ← 兜底：没有就补一段短的
```

---

### 卡点 10｜互动写成了单向

**卡在哪**：模型把"A 影响了 B"当成互动，但普通配对是**相互**的 —— 状态本身对称，两边同时被对方改变。

**怎么解的**：**用表格的列强制双向**。

| 两处 | 前者带给后者 | 后者回给前者 | 合起来是什么 |
|---|---|---|---|

**单向句填不进第二列**，所以模型必须两边都写。

**例外**：歧点（整体流出）和瑕点（碎片流入）**真的是单向的**，它们有自己的表。

---

### 卡点 11｜结构段太生硬

**卡在哪**：9 个小标题（合成整体 / 整体影响 ×4 / 瑕点流入 ×4），读起来像目录。

**怎么解的**：**一句话 + 一张流向表**。

```
这条流从"皇帝＋逆位公正"这个合成体出发，单方向下渗透，再经位置6拆成碎片注入后四张。
| 类型 | 从 | 到 | 搬过去的是什么 | 落点变成什么 |
```

**「从 / 到」用位置名**（现状、理想未来、自身），不是"位置1+2"这种编号。

---

### 卡点 12｜通用和塔罗混在一份文档里

**卡在哪**：`01_方法论.md` 既讲五步法，又讲正逆位、颜色三对、6 行表 —— 读者分不清哪层是方法、哪层是塔罗。

**怎么解的**：拆成两份 + 目录分层。

```
docs/公开/
├── 01_通用框架/   ← 本体：01_象征物体系.md、引擎分层说明.md、方法论流程图
└── 02_塔罗分支/   ← 分支：02_塔罗体系.md、塔罗推理链
```

**判据**：这份内容**换一个领域还成立吗**？成立 → 通用；不成立 → 分支。

---

### 卡点 13｜公开会不会把实现送出去

**卡在哪**：仓库要公开，但里面有参数、Prompt 策略、牌阵清单。

**怎么解的**：**三层隔离 + 白名单导出**。

| 层 | 放什么 |
|---|---|
| `repo\` | 公开成品：通用引擎 + 玩具领域层 + 两份文档 + 两张图 |
| `docs\公开\` | 公开的**源**，`export_repo.py` 复制到 `repo\` |
| `docs\私有\` + `system\` | 不公开：参数、Prompt、牌阵、商业与合规 |

**判据**：**机制名可以送人，规则和参数不送。**

---

### 卡点 14｜合规红线

**卡在哪**：输出越像"解读"，越容易滑向预测、断言、建议。

**怎么解的**：三条线 + 一张词表，每次全量扫。

| 线 | 禁什么 |
|---|---|
| 不预测 | 会 / 将 / 必然 / 注定 / 肯定 |
| 不断言 | 你其实是想 / 内心是为了 / 真正害怕的是；**以及任何主语的"其实是想"** |
| 不引导 | 应该 / 建议 / 不妨 / 先…再… |

**踩过的坑**：
- 「命运」连牌名都不能出现（Wheel of Fortune 不能译成"命运之轮"）
- 「处方」有医疗联想，改说"解法 / 应对"
- 否定句会误报：**"这不是预言"** 和 **"这不是注定的事"** 都被词表扫中 —— 内容是对的，接受为误报

---

### 卡点 15｜字数

**卡在哪**：一开始卡得很紧（3 张 1300），结果每次都超。

**怎么解的**：**按实测重设**，不按想象设。

- 早期：硬压 → 推理变薄 → 弃
- 现在：**上限 = 实测 + 余量**；超 500 字以内可接受

**现在的上限**：圣三角 1.9–2k ｜ 感情十字 2.4k ｜ 二择一 2.1–3.3k ｜ 六芒星 3.4k ｜ 维纳斯 3.5k ｜ 圣杯 3.5k ｜ 工作关系 4.2k ｜ 凯尔特 4.4k ｜ 事业 4.8k ｜ 三择一 5.3k

## 三、被否决的思路（同样重要）

**这些是想过、试过、最后否掉的**：

| 否决的 | 为什么 |
|---|---|
| **量化属性强度** | 一量化就变成比大小，而含义不能比大小 |
| **逆位 = 反义** | 会把牌读死；应该是圆心偏移 |
| **牌阵共用一套提示词** | 不同牌阵的侧重完全不同；改成每个牌阵写自己的 `PROMPT` |
| **每张牌一个标题 + 三层** | 像清单；改成按组分段 |
| **互动写成段落** | 看不出双向；改成表格的四列 |
| **给示例** | "我不想给示例，我需要给它空间" |
| **规定格式模板** | "可读性是核心，其他自己判断" |
| **话题硬拦截做在程序里** | 交给网站声明；程序只做红线 |
| **把内部图当对外图** | 会覆盖对外图（真踩过：`export_repo.py` 早期映射错过） |

---

## 四、现在的边界（明确不做的）

| 不做 | 为什么 |
|---|---|
| 不承诺预测 | 它给结构，不给保证 |
| 不做英文输出 | 以后再说；报告里也不混英文 |
| 不在程序里做话题拦截 | 网站声明层负责 |
| 不存报告 | 入口只输出，不落盘（提问文本也不落库） |
| 不量化 | 属性的变化只服务含义 |

---

## 五、如果重来一次，哪几步是关键

按重要性排：

1. **把"象征物"和"象征物本体"分开** —— 没有这一步，后面全是拍脑袋
2. **三态 + 关系位** —— 让"结论"从"算"变成"读"
3. **圆心 + 偏移** —— 逆位才有得推
4. **未组合元素 + 同景同类目** —— 互动才不是乱配
5. **歧点 / 瑕点** —— 多张牌才有"整体"，不是一堆并列
6. **分组 + 互动表 + 小结** —— 输出才读得下去
